# MaaTUI

本地 [maa-cli](https://github.com/MaaAssistantArknights/maa-cli) 的轻量 TUI 控制壳。

MaaTUI 负责调用 `maa`、编辑 `daily` 配置、展示分级日志和控制任务启停；不嵌入 MaaCore。

## 功能

### 每日任务

- 通过独立运行页执行 `maa run daily -v`
- 主菜单和配置编辑页不再挤占日志区域
- 运行中除日志外显示当前任务进度，例如 `当前进度：[1/7] 启动游戏`
- 进度总数按 daily 配置中的全部任务统计，包括禁用任务
- 运行中显示明确的停止操作
- `SIGTERM` 后超时使用 `SIGKILL` 清理整个进程组

### daily 配置管理

自动定位以下唯一一个配置文件：

- `~/.config/maa/tasks/daily.toml`
- `daily.yaml` / `daily.yml`
- `daily.json`

支持：

- 开启、关闭任务
- 上移、下移任务
- 新增和删除常用任务
- 编辑任务名称、基础参数和高级参数
- 客户端、连战次数、基建模式、无人机用途、临期理智药等使用带说明的选项
- 招募星级、设施顺序支持多选；普通文本仍保留自定义输入
- 关卡选择器支持常驻关卡、活动热更新目录、按接口时区计算的开放状态和掉落说明，也可输入自定义关卡
- 选择“当前/上次作战”会保存空 `stage`，由 MaaCore 识别游戏当前或最近一次作战入口
- 在任务编辑的关卡字段按 `v`，可创建 `OnSideStory` 活动变体；直接选择关卡仍保存为固定 `stage`
- 编辑、移动和删除条件变体；UI 可编辑基础条件，已有 `And` / `Or` / `Not` 组合条件会原样保留但暂不支持可视化修改
- 每个完成的操作自动原子保存

TOML 使用 `toml_edit` 修改，尽可能保留注释、布局和未知字段；YAML/JSON 会保留配置语义和未知字段，但保存后可能规范化排版。

配置目录和文件应保持用户私有；MaaTUI 默认拒绝通过符号链接写入受控目录之外的文件。

### 自动肉鸽

主菜单新增与“每日任务”“自动战斗”同级的 **自动肉鸽** 入口，不会把肉鸽任务加入 daily。页面有“控制面板”和“高级设置”两个页签，下方使用独立的“自动肉鸽日志”。

设置保存到：

```text
${MAA_CONFIG_DIR:-${XDG_CONFIG_HOME:-$HOME/.config}/maa}/maatui/roguelike.json
```

控制面板包括：

- 肉鸽主题：傀影、水月、萨米、萨卡兹、界园、黑流树海
- 难度（`-1` 表示不指定）与策略
- 开局分队、职业组、开局干员；分队和职业组支持自定义输入
- 凹开局策略下的烧水分队

高级设置会按主题和策略动态显示 MaaCore 参数，包括探索/投资次数、是否投资、最终 Boss 或等级停止条件、助战、凹开局奖励、密文板与坍缩范式检测、月度小队、深入调查、固定种子和黑流树海策略。具有上下文默认值的布尔项提供“跟随 Core 默认 / 开启 / 关闭”三态；多选字段支持 `Space` 勾选，也可用逗号或分号输入。

支持的策略为通用的刷分（`0`）、刷源石锭（`1`）、凹开局（`4`）、月度小队（`6`）、深入调查（`7`）；萨米额外提供刷坍缩范式（`5`），黑流树海提供培育襁褓动物（`30001`）。模式 `2` 已弃用，模式 `3` 仍在开发，因此不会出现在选择器中。

运行时 MaaTUI 会在 Maa 配置目录的 `tasks/` 下生成一个不以 `daily.` 开头的、仅含一个 `Roguelike` 任务的临时 JSON，并执行：

```text
maa run <temporary-task-name> --batch -v
```

任务结束、启动失败或退出 MaaTUI 时会清理该文件。旧版 MaaCore 不支持的新主题或策略不会被静默降级，错误会保留在自动肉鸽日志中；请先通过“更新管理”更新 MaaCore 与基础资源。自动肉鸽正常完成或异常退出会发送桌面通知，手动停止不会通知。

自动肉鸽页面快捷键：

- `↑/↓` 或 `j/k`：选择运行入口或设置字段
- `Enter` / `e`：运行或编辑当前项目
- `r`：直接运行自动肉鸽
- `Tab` / `←/→`：切换控制面板与高级设置
- `Esc` / `q`：返回主菜单

### 自动战斗与作业集

自动战斗页将独立单作业和批量作业集分开管理。作业集条目、运行设置等持久化数据位于：

```text
${MAA_CONFIG_DIR:-${XDG_CONFIG_HOME:-$HOME/.config}/maa}/maatui/copilot-set.json
```

远程作业正文缓存在同目录的 `copilot/` 下，不依赖 maa-cli 的可清理缓存；单作业页当前选择只保留在本次 MaaTUI 会话内，不写入上述列表文件。

支持三个页签：

- **单作业**：不保留历史列表，只在当前 MaaTUI 会话内保留一个“当前作业”；关闭 MaaTUI 后会清除，重新打开后需再次搜索。按 `e` 或 `a` 搜索/替换作业；输入框内按 `Ctrl+U` 可快速清空。运行前必须由用户在游戏内手动打开目标准备界面，单作业模式不会自动寻找关卡；同时支持普通与突袭的作业可按 `Space` 切换本次运行模式。
- **作业集（批量）**：保存可排序、可独立启停的有序任务列表。按 `a` 默认添加完整作业集；输入弹窗会高亮当前添加类型，按 `←` 固定选择“作业集”，按 `→` 固定选择“单个作业”，重复按键不会反向切换，也不使用大小写 `A` 区分。批量列表中的条目无论来自作业集还是单个作业，均继续持久化。
- **运行设置**：共享自动编队、助战、理智药等运行参数，并在修改后立即原子保存，重启 MaaTUI 后继续复用。

旧版缓存升级时会清除旧的单作业选择并提示重新搜索；已有作业集条目的顺序、难度和启用状态保持不变。此后单作业选择只在当前 MaaTUI 会话中存在，作业集和运行设置仍可跨会话复用。

`prts://` 新协议通过紧跟协议头的 `s` 区分作业集；`maa://` 是不携带类型的旧协议，由弹窗当前模式判定。仍接受尾缀形式 `maa://123456s`、`prts://123456s`。

完整作业集会通过作业站接口展开。向批量列表添加单个作业时，新条目始终追加到列表末尾：`difficulty=3` 按普通、突袭顺序追加两项，只支持一种模式时只添加对应项。单条下载或解析失败不会丢弃同一作业集中其他成功项。

作业集列表支持：

- `Space` 启用/停用当前条目并立即原子保存
- `t` 统一切换：只要存在启用项就全部禁用；全部禁用时则全部启用
- `c` 二次确认后清空整个批量列表，不影响当前单作业
- `i` 查看当前条目的关卡、干员、技能、模组、替换组和备注
- `d` 二次确认删除当前条目
- `Shift+↑/↓` 调整顺序
- `Enter` / `e` 单独运行当前条目
- `r` 批量运行全部启用项
- `Tab` / `←/→` 切换页签

底部状态栏按当前页面和终端宽度显示高优先级操作；普通页面在空间允许时保留 `?全部`，按 `?` 可打开当前页面的完整快捷键帮助。快捷键不会因为列表为空或当前状态而从帮助中隐藏；操作暂时无法执行时，状态栏会直接说明原因。输入、选择、确认和详情弹窗打开时，底栏会切换为当前弹窗自己的操作提示。

批量模式直接向 MaaCore 传递 `copilot_list`，支持普通/突袭混排和多关卡导航：

- 多作业强制开启自动编队
- `loop_times` 仅用于单作业，批量模式固定每项执行一次
- 单作业、单独运行的批量条目和完整作业集都会在运行控制栏显示当前进度，例如 `当前进度：[3/9] TO-3 · 作业标题`
- 每项识别到三星结算后立即自动停用并保存
- 任一项失败时 MaaCore 立即中止；失败项及后续未执行项保持启用
- 用户主动停止时，仅已经确认三星成功的项目会停用

共享设置包括自动编队、编队编号、理智药、补低信赖、忽略练度要求、助战模式、指定助战和单作业循环次数。

日常配置页对所有选择型字段在外层显示中文标签，例如 `series=0` 显示 `AUTO`、`drones="Money"` 显示“贸易站：龙门币”、`mode=0` 显示“默认模式”、`formation_index=0` 显示“当前编队”；进入选择弹窗后仍同时展示中文标签和原始值。

> 连战上限说明：虽然当前游戏客户端已经出现更高连战次数，但 MaaCore v6.16.2 及当前上游实现仍明确限制 `series` 为 `-1..=6`，并按 6 项列表识别。因此 MaaTUI 暂时只提供 AUTO、禁用切换和固定 1–6 次，避免保存 Core 会拒绝的 7–10。

当前限制：

- 暂不支持 SSS / 保全派驻作业及作业集
- 部分活动由 MaaCore 上游明确不支持多作业导航，此时仍可加入列表并单独运行
- 批量进度依赖 MaaCore `asst.log` 的逐关成功回调；MaaTUI 会按当前 maa 子进程 PID 过滤日志，若监视失效会停止批次以避免错误停用项目

### 桌面通知

每日任务和自动战斗在正常完成时发送普通 Linux 桌面通知，在启动失败、非零退出或内部错误导致中断时发送高优先级错误通知。通过 `Esc` / `Enter` / `s` 手动停止，或通过 `q` 停止并退出 MaaTUI 时不会通知；更新管理任务也不通知。

通知通过 `notify-send` 发送。通知命令不可用或桌面通知服务拒绝请求时，只会在当前任务日志中记录警告，不会改变任务本身的成功或失败状态。

### 更新管理

主菜单提供两个需要二次确认的手动更新入口：

- **仅更新活动与导航资源**：执行 `maa hot-update --batch -v`，更新 MaaResource，不更新 MaaCore 和随包基础资源
- **更新 MaaCore 与基础资源**：执行 `maa update --batch -v`，按 maa-cli 已配置频道更新核心运行库与随包基础资源，适合修复 OCR 或兼容性问题

更新过程复用任务日志与停止控制，不会阻塞 TUI 事件循环。

热更新成功后，MaaTUI 会读取 `maa dir hot-update` 下的 `resource/version.json`，在日志中展示活动名与 `last_updated`。若命令成功但版本未变化，会给出警告，避免“报告成功、实际未拉到新提交”的假成功。

### 自动战斗与地图资源

新活动关卡的 copilot 依赖三样东西：

1. 最新 `Arknights-Tile-Pos`（随 MaaResource **热更新**）
2. 足够新的 **MaaCore**（局内关卡 OCR / 导航逻辑）
3. **关卡码别名**：maa-cli 用「Tile-Pos **文件名以 `stage_name` 开头**」查找地图；作业常写 `TO-1`，资源文件却是 `act53side_01-....json`。MaaTUI 会在启动自动战斗 / 热更新成功后，按 `overview.json` 为缺失前缀的 code 生成 `TO-1.json` → 真实文件 的符号链接

日志形态不同，处理也不同：

```text
# A. 字母 O 写成数字 0 —— 优先升级 Core
Failed to find Tile-Pos file for T0-1, your resources may be outdated
```

作业实际是 `TO-1`（如 `maa://98652`），但旧 Core（例如 6.14.x）可能把 **TO** OCR 成 **T0**。
上游自 **MaaCore ≥ 6.16.0** 修复「直到大地变成一颗酸橙」的 TO→T0 问题。处理：

1. 「更新管理」→ **更新 MaaCore 与基础资源**（`maa update --batch -v`）
2. 确认 `maa version` 中 MaaCore ≥ 6.16
3. **仅热更新资源通常不够**

```text
# B. 关卡码本身正确但仍缺图 —— 热更新 + 别名
Failed to find Tile-Pos file for TO-1, your resources may be outdated
```

处理顺序：

1. 「更新管理」→ **仅更新活动与导航资源**
2. 确认日志中的活动名 / `last_updated` 已前进
3. 用 MaaTUI 再跑一次自动战斗（会自动补齐关卡码别名）；或确认 `Arknights-Tile-Pos/TO-1.json` 存在
4. 若仍失败，检查 `maa dir hot-update` 的 git HEAD 是否落后 remote
5. 再考虑 `maa update` 刷新 Core 附带基础资源

MaaTUI 会在任务失败时根据日志自动追加对应提示。

### 分级日志

MaaTUI 强制使用 `MAA_LOG_PREFIX=Always` 获取可解析的日志等级，并分别显示：

- 普通：中性浅色
- Info / 系统：青色级别标记，中性浅色正文
- Success：绿色级别标记，中性浅色正文
- Warn：黄色
- Error：红色
- Debug / Trace：灰色

日志颜色使用固定 RGB，避免终端主题把 ANSI 青色重映射成黄色；同时不会再把 maa-cli 写入 `stderr` 的所有普通日志一律显示成黄色 `!`。

## 前置条件

- 已安装并配置 `maa-cli`
- `maa` 在 `PATH` 中；MaaTUI 负责发现、调用和更新编排，不复制或接管 maa-cli、MaaCore 与资源文件
- 配置、数据、日志和资源目录遵从 `maa dir ...` 及 `MAA_*` / XDG 环境变量
- 存在 `daily` 任务（`maa list` 可确认；自动肉鸽本身不依赖 daily 配置）
- MaaCore / maa-cli 支持集成战略 `Roguelike` 任务；使用黑流树海或新策略时应先更新 Core
- Linux 终端（当前停止实现使用 Unix 进程组信号）
- 可用的 `notify-send` 与桌面通知服务（缺失时任务仍可运行，但不会显示桌面通知）

## 构建与运行

```bash
cargo build --release
./target/release/maatui
# 或
cargo run --release
```

## 设计原则

- **壳与内核分离**：实际游戏自动化由 maa-cli / MaaCore 负责
- **安全写入**：配置先写同目录临时文件，再原子替换
- **未知字段保留**：避免 MaaCore 或 maa-cli 新字段被编辑器误删
- **轻量运行**：同步事件循环、日志读取线程和有界日志缓冲，无异步运行时
